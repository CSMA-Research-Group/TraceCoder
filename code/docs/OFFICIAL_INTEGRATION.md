# 官方基线整合说明 · 2.1.0

本版将官方 WebDemo 的产品入口、Flask 页面组织、示例与核心提示词，整合到论文算法一致、可留存执行证据的系统中。2.1.0 是本地工程交付版本，不代表上游仓库发布了此版本。

| 基线 | 固定提交 | 使用方式 |
| --- | --- | --- |
| 官方 main | `cbd536eb5a02b53ee835cae2f07f5b7ed8bb694d` | 研究流程、数据与评测参考；三个核心提示词正文原样提取 |
| 官方 TraceCoder-WebDemo | `49beb48ce6d62cfd97b4714fbc8c1887879af43f` | Flask 页面/API 组织，需求＋测试入口，12 个原始示例 |
| 本地 2.0 系统 | 整合前备份及逐文件哈希 | 论文状态机、结构化执行器、项目版本、队列、证据和深色界面 |
| 已发表论文 | DOI `10.1145/3744916.3773187`，§3，Algorithm 1/2 | 官方实现与算法有差异时，以明确算法分支约束核心行为 |

官方两个分支没有共同祖先，未进行强行 Git 合并。本次为有来源映射的代码整合；原检出、历史、原始论文和数据均保留。研究目录的 `news/COMPARISON.md` 是整合前比较，不修改成新版本验收报告。

## 具体保留与修正

| 部位 | 原基线情况 | 整合后行为 |
| --- | --- | --- |
| 三个智能体提示词 | 官方 instrumentation / analysis / implementation 三个构造函数 | 正文保留在 `tracecoder/official_prompts.py`；外层补充数据边界与探针约束 |
| HLLM | 历史实际提示最多取两条，缺少完整候选代码 | 所有未全通过候选的计划、源码、反馈与分数进入后续分析 |
| Rollback | 主要按是否严格提升更新代码 | 按 Algorithm 2 的四个分支处理，单独维护上一尝试分数 |
| 网页测试判定 | 解析输出文字；超时和跳过存在误判成功路径 | 执行器生成结构化逐项结果；非空有效测试全通过才成功 |
| 顶层 assert | 正则转 unittest，受表达式空格影响 | AST 包装断言，保留原输入和比较表达式，失败后继续记录 |
| 运行参数 | 四个网页字段未进入 runner 参数 | 修复轮数、停滞、执行超时、插桩开关全部进入保存的 Config |
| 生成流程 | 需求＋测试即时运行 | 可先保存不可变版本；初始生成只接收需求，固定测试用于后续执行 |
| 模型与停止 | 全局客户端/停止状态，浏览器保存密钥 | 服务端环境配置，独立运行对象，停止须指定 run_id |
| 历史 | 浏览器本地记录，成功状态存在预设路径 | 持久化记录实际状态、测试结果与停止原因；打开历史不重跑 |
| HTTP 进程 | Flask 开发服务器 | Waitress 单进程 + 有界修复队列 + 状态目录锁 |
| 界面 | 官方首页、生成、历史、示例、设置、帮助 | 保留页面入口，扩展项目/工作台/部署；本地资源、深色响应式界面 |

`/api/run_tracecoder` 保留路径但改为 **202 异步作业协议**，返回运行 ID；旧客户端的 `steps` 返回结构需迁移。流式接口返回 `run/step/result/resume` 事件；最多 25 秒后释放连接，后续按运行 ID 查询。完整协议见 [API.md](API.md)。

## 入口与数据对应

- 页面：`web_demo/templates/`；同一 Jinja 外壳避免切页后丢失正在跟踪的任务。
- 业务服务：`tracecoder/service.py`；所有生成/修复 HTTP 入口进入同一 `Workbench.create → Run.execute`。
- CLI：`cli.py` 直接调用同一 Run、Config、Provider 与 Runner。
- 官方示例：`data/official/examples.json` 与上游 12 个对象一致。加载时在需求中显式补充测试引用的接口名称，原始测试保持不变。
- 来源清单：`provenance/UPSTREAM.json` 保存官方提交、来源文件 SHA-256 和迁移映射。
- 核心逐项对应：[PAPER_MAPPING.md](PAPER_MAPPING.md)。
